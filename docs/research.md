# Зерттеу: ауруханадағы атрибутқа негізделген қолжетімділік

Жоба жеке орындалады. Негізгі мәселе бастапқы репозиторийдегі «Проблема» құжатынан алынды:
рөлді ғана тексеру бөлімді, әрекетті, құрылғыны, уақытты және шұғыл жағдайды ескермейді.
Ішкі ұйым деректері сұралмады, пациент деректері пайдаланылмады.

## Ашық ұйымдық контекст

Оқу моделіне мысал ретінде Қазақстандағы University Medical Center (UMC) алынды.
UMC ресми сайты медициналық орталықтар мен клиникалық академиялық департаменттерді
сипаттайды. Бұл көп бөлімді ортаға арналған қолжетімділік моделін таңдауға негіз болады.
Дереккөз: [UMC туралы](https://umc.org.kz/about-umc/), [ресми сайт](https://umc.org.kz/),
қаралған күні 2026-11-27. Сайттағы клиникалар/төсек орындары сандары беттер арасында
әртүрлі болғандықтан, бұл модель ондай сандық деректерге сүйенбейді.

**Шектеу:** төмендегі рұқсаттар UMC-нің нақты ішкі қауіпсіздік саясаты деп көрсетілмейді.
Олар студенттік жүйеге арналған жобалық жорамалдар; ұйым жүйесінде осындай осалдық
бар деп мәлімдемейміз. Ұйым бұл жобаны мақұлдаған/қолданады деген тұжырым жоқ.

## Рөлдер және процестер

| Рөл | Оқу моделіндегі міндет/шектеу |
|---|---|
| doctor | Өз бөлімінің жазбасын корпоративтік құрылғыдан оқу (H1) |
| nurse | Өз бөлімінің жазбасын 08:00–18:00 оқу (H2) |
| doctor + emergency=true | Басқа бөлім жазбасын шұғыл оқу; H3 бөлек статистикаға түседі |
| nurse + prescribe | DENY (H4) |
| registrar + read | DENY (H5) |
| Саясат әкімшісі | JSON саясатын дайындап, тексерілгеннен кейін іске қосады |
| Аудитор | SQLite/CSV/JSON шешімдерін талдайды |

Саясат әкімшісі мен аудитор — консольдік құралдың актерлері; пайдаланушыларды тіркеу,
пароль, login экраны жасалған жоқ. Қозғалтқыш тек берілген контекстті бағалайды.

## Ақпарат ағыны және деректер

JSON саясаттары → immutable RuleNode ағашы → JSON сұраныстары → PolicyEngine →
AuditedEngine → SQLite audit_records → Stream есептері → CSV/JSON.
Сұраныс атрибуттары: role, action, device, department, record_department, time, emergency.
Әр шешім уақыт, әсер, policyId, себеп және контекстпен тіркеледі.

## Күтілетін әсер және өлшенетін қабылдау

Бөлім сәйкестігі жоқ дәрігер қарапайым оқу рұқсатын алмайды. Шұғыл қолжетімділік H3 арқылы
көрінеді. Құрылғы жоқ болуы NOT арқылы рұқсат жасамайды. Тыйымның басымдығы сақталады.
Негізгі көрсеткіш — тесттердің нақты өтуі және сегіз үлгі сұраныстың 3 PERMIT / 5 DENY нәтижесі.
Бұл оқу нәтижесі, нақты ұйымдағы қауіп азайғанын өлшеу емес.

## Келесі дамыту бағыттары

Атрибуттарды сенімді identity provider-ден алу; нақты дәрігер–пациент байланысын модельдеу;
аудитке өзгерту/өшіру рұқсатын шектеу; UI/REST; саясат версиялары мен басқарылатын reload.
Бұл мүмкіндіктер ағымдағы пакетте іске асырылған деп есептелмейді.

# abac
-ABAC саясат қозғалтқышы
Жобаның техникалық сипаттамасы (Java 17 + Maven)

1. ABAC қалай жұмыс істейді
Жүйенің жұмыс алгоритмі:
1. Бағдарлама іске қосылады.
2. policies.json файлының жолы алынады.
3. PolicyLoader JSON файлын оқиды.
4. Әр саясат үшін ереже ағашы (RuleNode) құрылады.
5. Саясаттар тізімі PolicyEngine-ге беріледі.
6. Сұраныс келеді: AttributeContext ішінде рөл, уақыт, құрылғы, орын және әрекет көрсетіледі.
7. Әр саясаттың шарттар ағашы сұраныс атрибуттарымен тексеріледі.
8. Нәтижелер deny-overrides ережесімен біріктіріледі.
9. Decision қайтарылады: PERMIT немесе DENY, себебі және сәйкес саясат id-і.

Ереже ағашы үшін Composite үлгісі таңдалды: жапырақ шарттар (ConditionNode) мен логикалық түйіндер (AndNode, OrNode, NotNode) бір RuleNode интерфейсін іске асырады, сондықтан кез келген тереңдіктегі ағашты бірдей өңдеуге болады.

5. Функционалдық талаптар
Бағдарлама:
• саясаттарды JSON файлынан оқуы;
• кез келген тереңдіктегі AND / OR / NOT ағашын құра алуы;
• рөл, уақыт, құрылғы және орын атрибуттары бойынша шарттарды тексеруі;
• бірнеше саясатты deny-overrides ережесімен біріктіруі;
• шешімге себеп болған саясатты көрсетуі;
• белгісіз оператор немесе қате JSON кезінде түсінікті қате беруі;
• түнгі уақыт аралығын (мысалы, 22:00–06:00) дұрыс өңдеуі керек.
6. Функционалдық емес талаптар
• Бағдарлама Windows және Linux жүйелерінде жұмыс істеуі керек.
• Қозғалтқыш сыртқы серверді қажет етпейді, кітапхана ретінде қолданылады.
• Саясат файлы кодты өзгертпей редакциялануы керек.
• Атрибут жоқ болғанда жүйе қауіпсіз жағына ауысуы керек (шарт орындалмайды, әдепкі тыйым).
• Код UTF-8 кодтауында сақталуы керек.
7. Негізгі техникалық қиындықтар
• Саясат қақтығыстары: бір сұранысқа PERMIT және DENY бірге сәйкес келуі мүмкін. Шешімі: deny-overrides.
• Түнгі уақыт аралығы: 22:00–06:00 үшін from > to, бөлек тармақпен өңделеді.
• Жоқ атрибуттар: сұраныста атрибут көрсетілмесе, шарт false қайтарады.
• Қате JSON: міндетті өрістер жоқ болса немесе оператор белгісіз болса, түсінікті қате шығуы керек.
• Уақыт форматы: тек HH:mm форматы қолданылады.
8. MVP нұсқасы
Бірінші жұмыс істейтін нұсқада:
• консольдік демо (Main) — орындалған;
• AND / OR / NOT ереже ағашы — орындалған;
• операторлар: eq, neq, in, not_in, time_between — орындалған;
• JSON-нан саясат жүктеу — орындалған;
• deny-overrides шешім қозғалтқышы — орындалған;
• кемінде 10 JUnit тест — жоспарда;
• қате JSON үшін валидация хабарламалары — жоспарда.
gt / lt / regex операторлары, саясаттарды жұмыс кезінде қайта жүктеу (hot reload), permit-overrides алгоритмі, REST интерфейсі және шешімдер журналы кейін қосылатын қосымша мүмкіндіктер ретінде қалдырылады.

# NOT және missing attributes: қауіпсіздік талдауы

Күні: 2026-11-27. Тексерілген бастапқы commit: `5035b9e1d308fc51b378863c94953ae013c9b7a6`.
Негізгі көздер — осы commit-тегі NotNode.java, ConditionNode.java, Policy.java,
PolicyEngine.java, PolicyEngineTest.java және README.md.

## Бастапқы жағдай

ConditionNode атрибут жоқ болса false береді; NotNode `!child.evaluate(ctx)` қолданады.
Policy шарты true болса өзінің әсерін қайтарады. PolicyEngine тек сәйкес DENY-ді іздейді;
ондай саясат жоқ болса сәйкес PERMIT рұқсат береді.

Осыған байланысты `PERMIT IF NOT(device EQ unknown)` және device жоқ сұраныс
бастапқы кодта PERMIT алады. Бұл README-дегі атрибут жоқ кезде қауіпсіз тыйым талабына қайшы.
NotNode түсініктемесіндегі ескерту қателікті құжаттайды, бірақ алдын алмайды.
Қате уақыт та false болып, NOT арқылы рұқсатқа айнала алады.

README үлгісінде doctor + жұмыс уақыты + NOT(device=unknown) нақты бар.
Дегенмен бастапқы repository tree-де **policies.json және policies-hospital.json жоқ**.
Сондықтан орналастырылған нақты саясаттардың қаншасына әсер ететіні анықталмады;
тесттер осы кодта шартты айналып өту мүмкіндігін дәлелдейді, болған шабуылды дәлелдемейді.

## Алдымен жазылған регрессия

`MissingAttributeSecurityTest` түпнұсқаның boolean API-імен компиляцияланады.
Ол атрибуттың жоқ/бос/null болуы, 1–6 NOT, AND/OR/NOT қабаттасуы,
жалғыз PERMIT, сәйкес емес DENY, анықталмаған DENY және жарамсыз уақытты қамтиды.
Осы файл бастапқы, содан кейін түзетілген кодпен орындалды. Санақ: verification/RESULTS.md.

Бастапқы толық жоба өз күйінде жиналмайды: pom.xml, аудит/репозиторий/batch кластары,
JSON үлгілері жоқ; HospitalPoliciesTest күткен бес аргументті ConditionNode конструкторы жоқ.
Сондықтан baseline үшін тек бар негізгі Java кластары, бастапқы ConditionNodeTest және
PolicyEngineTest, жаңа MissingAttributeSecurityTest стандартты Maven scaffold ішіне көшірілді.
Бұл baseline бүкіл бастапқы репозиторийдің тексеруі деп көрсетілмейді.

## Таңдалған шешім

Жапырақ missing/blank/invalid time кезінде `INDETERMINATE` береді. NOT бұл күйді сақтайды.
AND/OR strong Kleene логикасын қолданады. Тек шын/жалған мәндері бар ескі truth table өзгермейді.

| A | B | A AND B | A OR B |
|---|---|---|---|
| T | T | T | T |
| T | F | F | T |
| T | U | U | T |
| F | T | F | T |
| F | F | F | F |
| F | U | F | U |
| U | T | U | T |
| U | F | F | U |
| U | U | U | U |

`NOT(T)=F`, `NOT(F)=T`, `NOT(U)=U`.
Демек `NOT(NOT(U))=U`. Тек NotNode-де boolean false қайтару жеткіліксіз:
сыртқы тағы бір NOT оны қайта true ете алады. Сондықтан U бүкіл ағашта сақталады.

**Fail-closed шекарасы:** PERMIT саясаты тек TRUE болса рұқсат береді.
U PERMIT басқа толық дәлелденген PERMIT-ке бөгет емес; өздігінен рұқсат бермейді.
U DENY ықтимал тыйымды білдіреді, сондықтан басқа PERMIT болса да соңғы шешім DENY.
Нақты DENY әрқашан басым. Нәтиже саясаттардың орналасуына тәуелсіз;
бірнеше бірдей басымдықты саясат болса, reason/policyId бірінші табылғанын көрсетеді.

`TRUE OR U = TRUE`, `FALSE AND U = FALSE` әдейі сақталған. Мысалы,
`NOT(role=nurse AND device=unknown)` үшін role=doctor екені белгілі болса, TRUE дұрыс:
бұл жерде рұқсат жетіспеген device-тен емес, дәлелденген role салыстыруынан шығады.
Барлық атрибут міндетті болсын деген бизнес талабы бөлек AND шарттарымен берілуі керек.

## Сақталған және өзгерген behavior

- Қалыпты EQ/NEQ/IN/NOT_IN, толық атрибуттармен AND/OR/NOT — сақталды.
- Күндіз/түнгі [from,to) уақыт аралығы және шекаралары — сақталды.
- Missing leaf сыртқы boolean API-де әлі false; ішкі detailed API-де U.
- U DENY бұрын еленбейтін, енді рұқсатты бұғаттайды — қауіпсіздік үшін қасақана өзгеріс.
- Қате/екіұшты JSON ертерек қабылданбауы мүмкін: duplicate keys, trailing JSON,
  белгісіз өріс, object/null мәні, value+valueAttribute, артық values тексеріледі.
- JSON ағашының тереңдігі 128-мен шектелді. README-дегі шексіз тереңдік талабы
  stack overflow қаупіне байланысты нақты шекке ауыстырылды.
- Builder.attribute(name,null) алдыңғы мәнді өшіреді; ескі мәннің байқаусыз қалуы түзетілді.
- RuleNode іске асырушылары енді evaluateResult қайтаруы керек. Бұрынғы evaluate(ctx)
  шақырулары сақталады. Барлық кіріктірілген түйіндер бірге жаңартылуы міндетті.
- Policy.evaluate жаңа Effect.INDETERMINATE бере алады; PolicyEngine соңғы
  Decision ішінде тек PERMIT/DENY береді.

## Қосымша тексерулер және шектеулер

Атрибутты атрибутпен салыстыру, JSON loader, SQLite CRUD/қайта ашу,
параллель дәл бір рет жазу, SQL параметрлері, CSV escaping, Stream есептері тексерілді.
Аудит сақталмаса AuditedEngine рұқсат қайтармайды. Мұндай exception-ды сыртқы
бағдарлама PERMIT ретінде түсіндірмеуі тиіс.

Қозғалтқыш пайдаланушыны аутентификацияламайды, атрибуттарды растауға жауап бермейді,
аудитті криптографиялық түрде қорғамайды. Демонстрациялық саясаттар — оқу конфигурациясы.
Барлық кәдімгі құндылықтардың семантикасын (мысалы device="typo") автоматты түрде біле алмайды.
